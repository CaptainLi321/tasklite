# 0003 Discovery 已见语义维持现状:不引入 mark_seen,以占位任务表达「已见不处理」

## 上下文与决策动因

Discovery 的已见集合严格定义为 wall/failed 快照（`wrappers/discovery.py` 契约 S3/S4），
uid 进入二者的唯一路径是 spawn 子任务并经完成机器收尾。于是「进入 id 流、但业务回调
决定不 spawn 的 item」按定义永远未见：每 run 重遇重判，其所在页整页命中（T2）永不
触发，最坏退化为逐 run 白翻到 max_pages。

曾就「显式记见原语 `mark_seen`」做过完整契约论证：独立标记表、键与 process uid
同构、run 内 live 读 + 成功事务延迟写、协议分层能力探测降级。论证确认引入即**重开
契约**（S3/S4 定义域扩展 + T2 判定并入标记 + full 模式 on_missing 差集口径须重新
划定），并存在更轻的替代路径。

## 裁决

**不实现 mark_seen，不重开契约。**「已见不处理」以 spawn 一个占位子任务表达
（经正常终结路径进 wall）。

- 占位任务复用久经考验的既有机制，零框架代码、零新缺陷面；其代价（wall 混入
  占位条目稀释统计与审计口径、派发 wall 快照体量膨胀）属数据形态问题，不影响
  正确性（不漏不重），当前规模可接受。
- 前置判据：若「不处理」分类能在 `fetch_func` 内以**与新旧无关**的稳定谓词完成
  过滤，优先用过滤（零代码且 T2 正常刹车）；占位任务用于过滤不可行的场景。
- 过滤/占位任务的谓词**禁止依赖新旧信息**（如「只过滤旧条目」）——过滤后整页命中
  不再蕴含安全终止。

## 后果与重开条件

- 占位条目进入 wall 属本 ADR 明示的接受项：统计、审计、`clear_history` 等以 wall
  为口径的面均含此噪声；不得因「看着不对」顺手清理。
- 当「不处理」条目规模大到逐 run 重判/白翻页成本不可接受，或业务需要持久追溯
  「曾见不处理」时，重开本裁决。届时实现方向（经论证成立）：独立 seen 标记表
  （与 wall/failed 不共域，键与 process uid 同构、单射成立）、标记随 discovery
  job 成功事务原子提交、协议分层 + 能力探测降级保持框架无关；**必须**同步定义
  标记生命周期管理（删标记/批量清除及其与 `clear_history` 的联动关系——标记缺失
  时该 item 永判已见且无任何失败信号，比 wall 条目更隐蔽），并维持 full 模式
  `on_missing` 差集的 wall/failed 原口径（不纳入标记条目，宁可不报不可误报）。
