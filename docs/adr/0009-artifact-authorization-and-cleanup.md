## 1. 已确认的架构方向

### 磁盘是产物的可靠来源，具名描述用于引用

- 产物的共同引用身份为**完整 producer `job_uid` + artifact name**；Job UID 仍为 `task_type::job_id`，不只用局部 job_id 查找。
- 磁盘 output 支持调用方自定义文件或目录路径，适配外部工具的路径接口。目录不要求预枚举全部文件，不引入打包、递归快照或内容索引。
- 具名产物的描述数据随生产者的现有成功事务发布；失败或尚未确认成功的执行不能发布为成功产物。可以复用现有成功档案 metadata，不增加新的发布阶段或专用控制记录。
- 允许持久保存名称、规范磁盘路径及文件/目录类别等产物描述信息；它们回答「产物是什么、在哪里」，不是预留、确认、清理中、待释放等生命周期状态。公开签名及行为见第 5 节；描述元数据的具体存储形状由 A2 按这些行为实现。
- input 同时支持引用具名产物和直接使用外部磁盘路径。外部 input 不要求先登记为某个 Job 的 output。
- 消费者只读，不取得生产者路径的修改或删除权限。对外部工具交付路径不等于建立操作系统强制只读隔离，调用方仍须遵守只读契约。
- 用户显式声明 `depends_on`；查询时仅检查生产者 UID 属于当前 Job 的直接依赖，不扫描依赖图、不计算传递关系、不自动补边或创建 Job，也不增加调度分支或可关闭开关。正确的本批依赖顺序沿用 [ADR-0008](0008-trigger-contract-and-trusted-success.md)。

### 生产内存读取缓存暂不加入

- 本轮不实现独立纯内存产物，也不在 `declare_output` 加入生产内存缓存副本。
- 若将来代表性原型证明收益，再独立评估**默认关闭、仅文件 bytes、容量受限**的读取缓存；磁盘仍是可靠来源，缓存丢失只能回读磁盘。
- 缓存不能承诺磁盘产物丢失后自动恢复，也不能替代终态、spawn、cursor、声明或 suspend 的执行通信。
- 原型仍须计入真实 spawn 下的数据复制、动态读取通道、内存占用与缓存失效成本；未证明收益前不引入共享内存、请求协议或相应生命周期。

### IPC 是另一项工作

现有文件 IPC 继续承担执行结果与控制数据传递。具名磁盘产物不是 IPC 替代品；不能因为产物可以引用或未来可能缓存，就宣称可以删除 `.result.json`、声明日志或 suspend 通道。新传输的原型与选型继续由 I1—I3 独立裁决，本 ADR 不预选 Pipe 或其他实现。

## 2. 仍然保留的授权与路径规则

这些规则来自既有需求确认及本轮逐项审查，不因为撤回持久状态机而变为隐含删除权：

| 事项 | 已确认规则 |
|---|---|
| 三项删除权限 | `delete_existing`、`delete_on_failure`、`delete_on_success` 独立，普通 output 默认均为 `False`；记录这些权限属于声明授权数据，不是持久控制阶段 |
| 已有路径 | 没有 `delete_existing=True` 时明确报错；失败清理或成功清理权限不能代替前置删除授权 |
| 删除与回滚 | 显式删除不承诺备份、回滚旧内容或跨多个路径原子回滚；目录部分删除失败后不恢复已删部分 |
| 目录授权 | 声明代表整个产物目录，无额外递归开关；共享目录应声明专属文件或子目录 |
| 动态声明 | 声明与可执行的本地检查须早于首次写入，允许 handler 中途才知道路径；不要求启动前预枚举 |
| `declare_cache` | 仍指**临时磁盘产物**，是 output 的薄封装，固定成败清理；已有路径仍须独立前删授权，不保留独立 cache 清理状态机 |
| 成功存在性 | `delete_on_success=False` 的保留产物成功前须存在；`delete_on_success=True` 的临时路径可以已被 rename 而不存在，存在时需执行所授权清理 |
| 重复声明 | 同一执行对同名称、同路径、同权限及范围的声明幂等，不二次前删；中途改变名称、权限或范围明确拒绝 |
| 同执行路径重叠 | 同 Job 的目录与内部子路径也不重复声明；选目录整体，或选互不重叠的专属文件集合 |
| 跨 Job 写入 | 由用户承担路径独占与正确依赖约定；不再承诺框架通过持久预留或跨 worker 全局接纳阻止冲突。不得并发写同一或重叠产物，也不得改写其他执行正在使用的 input |
| 叶节点链接 | 拒绝符号链接及断链，不把声明链接解释为删除目标的权限 |
| 父目录链接 | 只接受规范化后仍满足允许范围的安全父目录链接；返回规范路径，删除前重新检查路径与父目录身份，不能把一次 resolve 当作永久安全证明 |
| 目录内链接 | 清理目录时只移除链接本身、不跟随目标；无法证明安全的挂载点或重解析点拒绝递归删除并明确报错 |
| 根与引擎目录 | 文件系统根、盘符/共享根、配置输出根本身不可声明为业务产物；状态和 IPC 目录及其全部后代也不可声明，祖先目录不能整体覆盖它们；输出根内的专属后代可声明 |
| `sandbox=False` | 保留具体路径的沙盒豁免，不豁免根保护、状态/IPC 区域保护或独立删除授权 |
| 重试保留文件 | 失败默认保留后，后续尝试遇到已有路径而无前删授权仍会报错，不为使重试继续而隐含删除旧内容 |

`declare_cache` 的“临时磁盘产物”与未来可能引入的“内存读取缓存”是不同概念，不复用术语来暗示相同生命周期或实现。生产者成功后留在磁盘上的文件也不构成永久独占登记；后来不同 Job 使用该路径仍须遵守独占约定，删除旧路径需其自己的明确授权。

## 3. 不新增持久控制状态的具体含义

不增加控制表、控制记录类别、持久阶段字段，也不把以下信息藏入既有 queue、metadata 或 JSONL：预留成功、父进程已接纳、等待可写确认、清理中、清理完成、待释放等。产物描述与三项授权数据允许表达，但不得借此重建被否决的状态机。

最小实现优先在现有执行边界内处理声明、路径检查、删除和错误：同执行的重复/重叠声明可以从当前声明记录校验，不要求新增全局内存索引或同步父确认协议。跨 Job 互斥由用户契约承担，已有同 uid 执行锁仍保留，不能与孤儿 worker 并行执行。

### 清理、提交与崩溃的边界

- 对当前进程已经观察到的成功结果，必要成功清理先于现有成功事务；清理失败必须可观察，不能仍报告该次成功，也不把基础设施错误额外计入 handler 故障重试预算。
- 实施时必须与现有收割边界一起处理：输入声明需要在删除声明文件前读取，清理异常不能被 finally 吞掉，已有队列保存和进程回收路径也不能被异常中断。这里要求修正现有调用顺序，不引入完成结果收件箱。
- 原方案的“清理失败后跨 run 持续冻结 handler、自动恢复每项清理债务、完成后自动释放路径所有权”承诺撤回。现有输出日志可以作为声明数据和诊断依据，但不能把保留日志直接解释为可靠的接纳或清理阶段证明。
- 主进程或 worker 在未确认成功前崩溃，仍按既有模型允许重做。没有持久结果收件箱，因此不保证恢复原始完成结果，也不保证自动识别并补完原成功/失败模式的清理；不能宣称基础设施错误后绝不会再次执行 handler。
- 对无法判断归属或阶段的残留，不得凭猜测扩大删除权限。后续实现须把报错、日志保留及人工处置边界明确交付，不能默默当作自动清理恢复保证，也不能为这些处理新增持久控制阶段。
- 具名记录存在不等于磁盘对象仍存在。查询必须检查实际对象；缺失时明确报错，保留成功历史，不自动清历史、补跑生产者或添加调度特判。

## 5. 已接受的公开接口与引用行为

以下公开接口已由 A3 接通并通过最终验证，收尾错误传播已由 A4 接通：

```python
def declare_output(
    path: str | Path,
    *,
    name: str | None = None,
    delete_existing: bool = False,
    delete_on_failure: bool = False,
    delete_on_success: bool = False,
    sandbox: bool = True,
) -> str: ...


def declare_cache(
    path: str | Path,
    *,
    delete_existing: bool = False,
    sandbox: bool = True,
) -> str: ...


def declare_input(path: str | Path) -> str: ...


def get_artifact_path(*, producer_job_uid: str, artifact_name: str) -> str: ...
```

所有路径返回值均为**产物自身的规范绝对路径字符串**，不是父目录，也不改为 Path 对象。可用 `Path(returned_path)` 包装后交给文件操作或外部工具。output/cache 的相对路径遵循输出根规则；直接 input 的相对路径仍按当前工作目录解析。

### 声明、命名与发布

- `path` 保持 output 的第一位置参数，`name` 是可选 keyword-only 参数。`name=None` 为匿名声明，仍须检查路径、验证产物并按三项授权清理，但不加入可跨 Job 查询的具名清单。
- name 是显式产物名，不从路径、job_id 或文件名自动生成；同一 Job 的单次成功内，名称与规范路径一一对应。拒绝同名异路径和同路径多名称；重复声明必须名称、路径、权限和范围完全一致才幂等，不二次前删。
- `delete_on_success=True` 的 output 不允许设置 name；`declare_cache` 没有 name 参数，精确复用匿名 output 的成败清理授权，不发布临时路径引用。
- `declare_cache(path, delete_existing=..., sandbox=...)` 等价于匿名 `declare_output(path, delete_existing=..., delete_on_failure=True, delete_on_success=True, sandbox=...)`，底层不保留独立 cache 状态机。
- 每次成功在现有成功事务内**整体替换**该 Job 的具名产物清单，包括本次没有具名声明时发布空清单；不把上次成功名称合并到本次清单。失败不发布本次描述。
- 某名称在新成功清单中消失，不授权删除其旧文件；删除只能来自相应路径已有的明确权限，不能从清单差异推导。
- 描述数据来自本次已声明的产物，不以业务返回 metadata 伪造声明清单。具体存储键及描述结构由 A2 确定，不新增发布/接纳/释放阶段字段。

### 查询与输入声明分离

`get_artifact_path` 只读取成功描述并查询路径，不执行 trigger 或成功基线计算，不自动调用 `declare_input`，不把查询行为登记为本次输入。调用方决定读取哪个实际路径，再显式声明输入；外部文件或目录继续直接使用 `declare_input(path)`，不要求具名生产者。

查询时强制检查生产者 UID 属于当前执行 Job 的直接 `depends_on`，仅做列表成员校验，不新增 Context 的公开 Job 属性。生产者可以是本批刚成功的 Job，也可以是直接依赖中有有效历史成功的 Job；不接受只因传递祖先存在而跳过直接声明。没有开关，不扫描依赖图、不补入依赖或修改调度。并非每个 depends_on 都必须读取产物，单纯顺序依赖仍合法。

满足直接依赖后，还须检查当前有效成功档案、名称和实际磁盘路径。查询返回生产者登记的文件或目录自身路径，不返回其父目录。消费者不取得写入或删除权限。

| 情形 | 错误归属与副作用边界 |
|---|---|
| 生产者不是当前 Job 的直接依赖 | 依赖约定错误，立即拒绝查询；不计算传递依赖或自动补边 |
| 没有该生产者的有效成功档案 | 成功产物查找失败，不借失败档案或未确认结果发布内容 |
| 有成功档案但没有该 name（包括新成功已移除的名称、历史或 seed 档案没有具名清单） | 视为该名称未发布，名称查找失败；不回退旧清单、不猜路径、不修改历史 |
| 描述仍在，但文件/目录已丢失 | 明确报告磁盘路径缺失；保留成功记录，不自动清历史或补跑生产者 |
| 路径不可访问或存在其他文件系统错误 | 明确传播对应路径错误，不伪装为空结果、缓存未命中或自动重建 |

上述错误分类不引入新持久状态或自动恢复流程；具体异常文案应包含生产者 UID、产物名及可用的路径上下文。接口实现按这些归属使用明确的参数/查找/文件系统异常，不把它们吞成 None。

### 目录与实际输入示例

目录不预枚举、不内置子路径选择器。调用方自行用 Path 组合后声明实际读取的文件；仅声明目录自身时仍只 stat 目录，不递归。

以下示例说明公开接口：

```python
from pathlib import Path
from tasklite import Job


def build(job, ctx):
    folder = Path(ctx.declare_output("bundle", name="bundle", delete_existing=True))
    folder.mkdir()
    (folder / "report.txt").write_text("result", encoding="utf-8")


def consume(job, ctx):
    folder = Path(ctx.get_artifact_path(
        producer_job_uid="build::daily", artifact_name="bundle"
    ))
    report = Path(ctx.declare_input(folder / "report.txt"))
    return {"text": report.read_text(encoding="utf-8")}


# 注册相应 Task 后，明确声明直接依赖；仅查询目录不会记录目录 input。
jobs = [Job("consume", "daily", depends_on=["build::daily"]), Job("build", "daily")]
```

本例只把 report.txt 作为实际输入，不把 bundle 目录自动加入 inputs。若消费者改为 `declare_input(folder)`，则只观察目录自身 mtime；若显式声明目录及文件，两者都属于输入。目录内部创建 report.txt 不需再次 declare_output，避免与目录声明重叠。

## 6. 验收与工作单边界

A2—A4 的实现与测试须覆盖：

- 具名与匿名 output 的差异；文件/目录自身的 str 返回值；临时路径禁止 name；三项独立授权和匿名 rename 用法。
- name↔规范路径的一一对应、完全一致的幂等重复、同名异路径及同路径别名拒绝；同执行目录/子路径重叠拒绝。
- 直接依赖缺失拒绝、仅传递祖先拒绝、直接依赖的历史成功可查，以及不读取产物的纯顺序依赖仍合法；无图扫描、自动补边、调度分支或关闭开关。
- 成功清单整份替换、空清单移除旧名称、失败不发布、清单移除不删旧文件；成功描述与已有成功事务同进退，不增加发布控制阶段。
- 无成功/无名称/磁盘缺失/路径不可访问分别明确报错，历史成功不被自动清除，生产者不被自动补跑。
- getter 不登记 input；目录经 Path 选实际文件后显式声明，目录本身只 stat 不递归；外部路径 input 保持可用。
- 三授权、链接与根保护、部分删除失败、当前执行内清理错误可观察，以及跨崩溃不保证清理恢复的边界。
- A1：用户已逐项及最终确认本 ADR 的方向、接口与直接依赖强校验，设计完成，状态为 Accepted；这不代表产物实现完成。
