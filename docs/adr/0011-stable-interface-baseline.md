# 0011 稳定 Interface 基线与主进程文件授权

状态：**已接受，待实施**。本记录固化接口定型讨论的最终决定，不代表当前安装版本已经提供这些能力；发布版本号、数据库版本号及下文列出的细节尚未冻结。当前使用仍以 [GUIDE](../GUIDE.md) 为准，实施及文档改版清单见 [ROADMAP](../ROADMAP.md#4-稳定-interface-基线与文档改版--已接受待实施)。

## 背景与取舍

长期兼容需要覆盖调用方式、默认行为、错误结果、持久记录和扩展协议，而不只是导入名。选择在新基线发布前集中整理 Interface，不为被替代的旧返回形式、参数和入口增加兼容解析；新基线之后遵守兼容承诺。Module 的内部状态机、注册表和可变运行配置不因可访问就成为稳定 Interface。

常用 Interface 分为编排运行、任务执行、状态访问与管理三类职责，不要求机械增加三个类。已有排序、重入队和触发器 Seam 与常用 Interface 分层维护，不增加新的调度算法。内部单一终结出口、单向依赖、单射编码及数据库写事务纪律保持。

本文有意替代既有 ADR 中涉及结果归一化、重试预算、执行选择、文件声明和通信方向的部分决定；其他决定不随之失效。尤其 [ADR-0010](0010-ephemeral-worker-pipe.md) 的“无响应需求”前提不再成立，但执行通信仍不持久化、不跨重启接续。

## 故障处置原则

借鉴民航“八该一反对”在条件不满足时采取明确处置、反对勉强继续的思想（[中国民航局说明](https://www.caac.gov.cn/XWZX/DFDT/200901/t20090105_21230.html)），本项目采用：该失败就失败，该停止就停止，该请求授权就请求授权，反对为了表面上的继续运行而猜测成功、隐式重试或堆叠恢复分支。这是工程原则类比，不是航空规则在本项目中的直接应用。

主进程异常退出后，本次在途、尚未提交成功的执行及其产物不再被当作可信完成。后续打开执行状态时将这些执行按失败收敛，保留完整 Job 快照及可得证据；原因不明则记录未知，不根据残留文件或迟到结果补造成功，不自动接续旧执行。已提交成功记录不受影响；从未派发的 pending 也不因主进程退出而改判失败。此决定明确替代旧 ADR 中对此类在途执行自动接续的恢复假设，正常 Ctrl+C 排空不属于异常退出。

不为父死子存场景增加孤儿产物抢救、执行权交接或清理与旧 worker 协作恢复协议。也不以“不可信”为理由扩大文件删除权：残留产物仍受用户授权、声明清理策略与受保护路径规则约束，框架不承诺其完整或静止。保留已有必要互斥；无法取得执行权或确认操作条件时明确拒绝或失败，不通过绕过互斥强行继续。不可靠不等于自动删除，也不等于杀死旧 worker 的保证。

## 编排、身份与启动

- 保留 Task 规格、Job 逻辑身份、Attempt 执行轨迹。Job 身份仍由 task_type 与 job_id 确定。
- 保留简式任务注册和 Task 对象注册。Job 不再让业务构造内部运行账目；只读属性和类型提示提供有限约束，不递归冻结业务 payload，也不检查业务代码是否修改对象。
- 公开 enqueue 本版本只提交一个 Job；框架捕获独立快照。同 UID 已排队时，相同内容幂等去重，不同内容明确冲突；替换未执行任务必须显式进行。不得顺带扩展批量事务或批量报告 Interface。
- ctx.spawn 同样捕获独立快照。外部单次提交与父任务一次成功中提交多个派生任务是不同场景，后者仍要求整体提交。
- Trigger 表达本次 Run 对已入队 Job 的启动规则。它不主动入队，也不控制一次启动后的故障重试。on_failure 改名 until_success，默认仍为 once。

| Trigger | 无终态记录 | 当前 successes | 当前 failed（含取消） |
| --- | --- | --- | --- |
| once | 执行 | 跳过 | 跳过 |
| until_success | 执行 | 跳过 | 执行 |
| always | 执行 | 执行 | 执行 |
| on_input_change | 执行 | 按输入变化契约判断 | 执行 |

这些判断消费当前终态档案，不搜索全部 Attempt 历史。on_input_change 暂保留可信成功时间与声明输入自身 mtime 的判断，不扩大为内容哈希、递归目录或输出缺失检测。

| 场景 | Trigger 求值 |
| --- | --- |
| 本次 Run 准备启动一个普通候选 | 依赖就绪后求值 |
| 同 Run 内由 TaskResult.retry 产生的再次尝试 | 不重复求值 |
| 新 Run 接续仍在 pending 的未完成任务 | 重新求值，不能凭旧 Attempt 编号跳过 |
| 终态任务重新入队成为普通候选 | 按当前 Trigger 求值 |

新 Run 重判 Trigger 与预算重置是两个独立规则，明确替代旧指南关于跨 Run 恢复继续沿用原启动判断的约定。异常退出后已收敛到 failed 的任务不自动回队；只有重新入队或显式管理重跑才再次成为候选。自定义 Trigger 的判断可能在两次 Run 之间改变，因此停止前曾获准执行不保证下次仍执行。

Trigger 返回 False 沿用“本次无需执行”语义，不等于 Selection 排除留队，不生成新的成功证据或产物；依赖处理与具名产物存在性校验仍需遵守原契约，不能因跳过生产者就认为其产物存在。

不增加“每 UID 每 Run 最多启动一轮”的特判。同 UID 再次成为候选仍走普通去重、依赖和 Trigger；同 Run 内再次入队不得刷新重试预算。

执行选择改为 run(selection=...)，只影响本次运行，被排除的任务及受影响下游留队。永久取消移至 Run 外管理操作：目标与依赖下游写入 failed，以框架原因区分主动取消和依赖取消，不增加取消集合。再次入队仍服从 Trigger，取消没有优先于 always 的特殊屏障。

## 结果、重试与记录

handler 只支持同步调用；正常返回必须为 TaskResult。主动表达只有同级的三个结果：

```python
TaskResult.success(metadata={"count": 12})
TaskResult.failure(message="无法处理", metadata={"reason": "unsupported"})
TaskResult.retry(message="暂时不可用", consume_budget=True, metadata={})
```

- 不再接受 None、bool、dict、二元组作为隐式结果。
- retry 的 consume_budget 默认 True；零预算重试必须显式 False。返回 retry 不隐式挂起资源，挂起资源也不隐式终止 handler。
- 未捕获异常、超时、worker 意外退出统一 failed，不自动归因后重试。能够捕获的异常、退出信息保留原文及实际证据；确实无原因才记录未知。不猜测原因。
- 不提供业务主动抛出重试异常的平行协议，也不保留异常类型自动映射重试。可恢复错误由 handler 捕获并返回 TaskResult.retry。
- 不增加默认等待、自动退避或零预算重试限次。文档说明没有资源挂起或自定义节奏时，零预算重试可能持续立即执行；节奏仍通过既有 RequeuePolicy Seam 扩展。
- HTTP 等 wrapper 必须适配显式结果协议，不再靠隐藏的重试异常控制 handler。

预算字段统一为 **max_retries_per_run**：每个 Job、每次 run() 独立，在内存计数，不新增持久化预算字段。首次执行之外，最多允许该数量的消耗预算重试。预算耗尽记 failed，不自动启动下一次 Run。同一 Run 再次入队保留消耗；新的 run()（包括同进程 stop 后再次调用）从零计算。跨进程重启不保留已消耗预算。

每次实际执行均推进 Attempt，包括零预算重试。未执行 handler 的锁冲突不伪造物理执行。Attempt 编号不是预算计数，不因预算重置而丢弃历史。

| 结果 | 业务 metadata | 派生任务与游标 |
| --- | --- | --- |
| success | 写本次 Attempt 与成功档案 | 全部校验通过后同成功事务提交 |
| failure | 写本次 Attempt 与失败档案 | 不发布 |
| retry | 写本次 Attempt；耗尽时带入失败档案 | 不发布 |

框架身份、时间、原因、输入和产物描述与业务 metadata 分离，不向业务字典注入保留键。metadata 采用严格 JSON 对象契约。

所有以 Job 为主体的记录都完整保存 Job 快照：队列保存已接纳的执行配置，successes 保存最近一次成功对应的配置，failed 保存失败或取消对应的配置，attempts 保存该次执行开始时的配置。快照包括身份、payload、依赖、FileSpec 和解析后的有效执行配置，不保存 handler 代码；handler 由当前注册 Task 提供。不通过可变的“最新 Job”记录间接引用历史。

人工重跑恢复失败档案的完整快照，不仅恢复身份与 payload，也不静默套用新 Task 默认值。max_retries_per_run 配置入快照，已消耗预算仍只在内存。动态文件声明、业务结果和框架原因单独记录，不倒改执行开始时的快照。游标、资源挂起和路径授权不是 Job 记录，不重复嵌入 Job 快照。

父成功、派生任务、游标必须整体接受和提交；坏子任务不再独立失败而允许父任务成功。数据库环境故障不得伪装成业务结果；保留未提交任务的恢复条件。资源挂起是独立即时控制效果；文件与外部请求不属于数据库事务，不能承诺回滚。

完成回调接收单个事件对象，包含 Job 身份、Attempt 信息、实际结局、业务 metadata 和独立框架原因。预算耗尽后的实际结局是 failure。回调错误只记录观测错误，不撤销提交或重试任务。不新增 interrupted 结果；停止与尚未完成记录的映射见后文。

## 统一文件声明

采用一个 FileSpec，kind 内置 input、output、cache；不保留三种分类类，也不在 Job 并列 inputs/outputs/caches。预声明与运行时声明采用相同配置：

```python
Job(
    "process",
    "item-1",
    files={
        "source": FileSpec("./inputs/source.dat", kind="input"),
        "result": FileSpec(
            "./results/result.dat", kind="output",
            delete_existing=True, delete_on_failure=True,
        ),
        "scratch": FileSpec("./results/tmp/item-1", kind="cache"),
    },
)

path = ctx.declare_file("extra", FileSpec("./results/extra.dat", kind="output"))
result_path = ctx.file_path("result")
```

上述为目标形态示例，不是当前可运行代码。declare_file/file_path 替代重复的运行期声明入口。

| kind | 行为 |
| --- | --- |
| input | 只读输入声明，参与输入变化判断，不接受删除策略 |
| output | 可发布的具名产物，按显式策略清理 |
| cache | 临时文件或目录，成败均清理，不发布为产物 |
| 自定义 | 内置行为的命名配置，不执行自定义授权、删除或清理代码 |

相同名称、相同声明幂等复用；同名不同声明报冲突。自定义 kind 必须先注册，声明解析为明确的内置行为及配置，不成为任意执行插件。

输入与输出均取预声明和运行时动态声明的并集，不采用一方替换另一方的规则。动态信息只有声明后才可见，不能反向影响已经完成的本次启动判断；成功记录保存合并后的声明，供后续观察和启动判断使用。不因引入预声明而新增“输入集合变化即强制重跑”的规则。

不同 Job 的同路径或重叠目录范围由使用者负责协调；框架不新增路径独占锁、冲突等待或运行时路径冲突判失败机制。主进程集中操作不等于保证业务文件并发安全，用户目录授权也不是独占许可。

所有相对路径按工作目录解析；output_roots 只限制框架操作范围，不隐式拼接路径。构造及入队只保存声明，不创建、删除或修改业务文件。执行顺序固定为：

**依赖就绪 → 输入及 Trigger 判断 → 路径授权 → 产物准备／前置删除 → 启动 worker。**

无需执行的任务不触发产物准备或删除。动态声明在调用时请求主进程授权与准备，完成后才返回路径。必须先声明获准，再写入；禁止本次写入后补声明。既有文件可以声明并显式要求覆盖，不以路径已存在就断定违规。

保留 delete_existing、delete_on_failure、delete_on_success 的时机区别。缓存固定成败清理，前置删除仍需显式配置。获得目录授权不等于框架可以任意自动删除目录内容。

## 主进程所有权、授权与通信

框架的前置删除、成功清理、失败／重试清理、停止清理和缓存清理全部由主进程执行。worker 只请求、等待准备结果及写入业务内容，不直接执行框架清理原语。

保护仅覆盖框架文件操作，不是操作系统安全隔离。不限制 handler 的直接文件访问，也不限制外部可执行程序写到其他位置；不承诺拦截所有写后声明。

- 读取默认允许。首次写入授权展示规范绝对路径；文件授权覆盖该文件，目录授权覆盖该目录树。写入、覆盖和删除不拆分用户授权粒度。
- 授权持久化，跨 Run 和进程复用，提供查询与撤销。同路径未来内容同样在授权范围内，实际目标变化需重新确认。
- 支持显式环境变量或命令行默认同意，记录实际授权路径；不绕过受保护路径等硬性禁止规则。
- 主进程询问。等待时暂停新派发，继续收消息、结算其他在途任务及处理超时；等待授权的 worker 不计执行超时。
- 拒绝授权或无法询问时，整个 Run 进入优雅停止：停止新派发，处理能正常完成的在途任务，解除所有受阻授权等待，然后以明确授权原因返回。受阻任务及尚未执行的依赖下游保留 pending，不消耗预算，不提交成功效果，不执行未经授权的退出清理；不得在同一 Run 再次派发并循环询问。外部停止同样撤销未完成授权等待。

动态声明现在需要“请求—主进程决定并准备—回复—worker 继续”的往返。因此扩展一次执行内的响应通道，绑定执行身份，拒绝过期回复并处理停止唤醒。传输选择留在 Implementation，不暴露给 handler；不增加持久消息、跨重启重连或自动补发删除。文件已删除但回复丢失时，不能声称文件副作用已回滚。

## 生命周期与观察

run() 可重复调用。stop() 只请求停止当前 Run；close() 释放资源且运行期拒绝调用，支持 with TaskLite(...) 自动关闭。正常阻塞 run() 返回后不要求再 stop()。

**主进程收到 Ctrl+C 的含义是停止新派发，等待当前任务完成后退出。** 不主动转发给 worker，不记成任务失败；终端可能向整个进程组投递 SIGINT，Implementation 必须保证 worker 行为符合该契约。当前任务仍受执行超时约束，完成结果与清理正常提交。未派发任务 pending。

等待授权的 worker 无法自然完成：停止时解除等待并保留 pending，不能无限等待或制造未知业务失败。已启动的本次 Attempt 记 failure，原因如实记录授权被拒绝或等待期间停止；Job 不进入 failed，不消耗预算，不发布成功效果。Run 不将它统计为终态 Job 失败。回调必须能区分 Attempt 失败与 Job 进入失败档案，并表达 Job 是否留队。不新增 interrupted 结果，不抹掉历史，也不永久保留 running。尚未启动 worker 的拒绝不伪造 Attempt。

运行摘要区分退出原因与完成程度：has_failures 只表示本次产生的终态失败；has_pending 表示结束时仍有队列任务，包含选择排除；is_complete 表示正常结束且没有本次终态失败、没有剩余任务。Trigger 跳过不等于实际成功执行，统计分开。

独立只读入口为 StateSnapshot，不再套外层 reader：

```python
with StateSnapshot.open(state_path) as state:
    record = state.get_success(job_uid)
    failures = list(state.iter_failures(task_type="process"))
    pending = list(state.iter_pending())
    attempts = list(state.iter_attempts(job_uid=job_uid))
    cursor = state.get_cursor("position")
```

一个上下文提供一致快照，可在执行期间打开，不创建、迁移、修复数据库。重新打开才看见新提交；迭代在上下文内完成，已返回记录关闭后仍可用。采用迭代／分页避免强制全量加载。公开数据结构稳定，SQL 表结构不承诺公开。待执行记录不是实时操作系统进程清单。

查询不提供写操作。管理操作仅限 Run 外；新增 resume_resource(name) 清除持久挂起，不改变限速或容量配置。不能通过修改查询返回值改变引擎。

Run 外限制以状态库级互斥落实，而非只检查当前 Python 对象：不同进程的执行与管理写操作互斥，同时允许多个 StateSnapshot 只读观察。不提供绕过执行／管理互斥的公开参数。该限制不妨碍当前执行器自身的状态事务与资源挂起持久化。

## 兼容承诺与非目标

本轮不提供旧库迁移。不支持的旧格式在只读检查后明确拒绝，不自动修复、覆盖或另建内容冒充恢复。开发、验证只使用新临时状态或显式副本，严禁修改、删除旧业务数据和旧业务数据库。

新基线之后：新版本继续支持旧公开调用和约定行为，能读取或有明确迁移路径处理受支持旧状态；同主版本不静默删除接口或改变默认语义。不能承诺旧版本理解任意未来新格式，格式支持窗口和回退方案必须发布。内部重构与兼容增加能力允许。

本次不增加分布式执行、操作系统级文件隔离、异步／生成器 handler、批量提交协议、额外调度算法或任意自定义文件执行插件。不记录具体消费项目身份或功能。

## 实施前需完成的细节设计

以下不是已接受的新行为，必须在实现前明确；不得用实现便利替代裁决：

1. 单次提交返回结构、显式替换和取消的签名；内容比较范围及规格默认值解析时机。FileSpec 的规范路径、kind 默认配置应避免跨工作目录或重注册后漂移。
2. Attempt 编号作用域、运行事件最终字段和统计键；不要让执行编号再承担预算计数职责，或把授权停止导致的 Attempt 失败误计为终态 Job 失败。
3. 按预声明与动态声明并集规则实现启动时可见的输入视图；输入由上游生成时的检查时机；不得未经决定更改 on_input_change 的含义。
4. 自定义文件类型注册签名、默认清理参数与具名上游产物引用；路径并发仍由使用者协调，不实现额外独占机制。
5. 授权存储位置、撤销与目标身份核验；环境变量和 CLI 的精确入口。CLI 仅提供授权接线，不顺带实施整套直达任务 CLI。
6. 按明确失败／停止原则实现清理故障、声明故障及状态写入故障的处置；操作完成而响应丢失时的确定性测试。不得扩展为孤儿执行抢救协议，或将资源挂起、锁冲突和通信故障重新混入业务异常启发式。
7. HTTP、Discovery、测试上下文如何适配显式结果及文件声明，不增加第二套隐式重试协议。
8. 发布版本、格式版本、具体兼容窗口；当前文档只在实现与验证完成后切换成新契约。

这些细节与已确认的大方向分别维护，防止把候选名称或未决状态误写成已发布承诺。
